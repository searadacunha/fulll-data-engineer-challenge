# Bike share statistics: fulll Data Engineer Junior challenge

<p align="center"><img src="assets/readme-hero.svg" width="100%" alt="fulll-data-engineer-challenge project banner" /></p>

My solution to the [Data Engineer Junior challenge](https://github.com/fulll/hiring/blob/master/DataEngineer/Junior/data-level-1.md)
that fulll publishes in its hiring repository. The program explores the bike share trips of
Chicago, New York City and Washington over the first half of 2017. For a city, a month and a
day of week chosen in the terminal, it reports:

- the most common month, day of week and start hour;
- the most common start station, end station and trip;
- the total and mean travel time;
- the number of trips per user type and per gender, and the earliest, most recent and most
  common years of birth.

The provided files are completed in place. `bike_investigation.py` keeps its functions and
their signatures, and `test_bike_investigation.py` keeps its `unittest` form and its first
test, which now passes.

## Quick start

With [uv](https://docs.astral.sh/uv/), which also installs the Python version the project
uses:

```sh
uv sync --locked                     # dependencies exactly as in uv.lock
uv run python scripts/fetch_data.py  # official data, checked against SHA-256
uv run python bike_investigation.py  # interactive session
uv run pytest                        # whole test suite
```

Without uv: Python 3.11 or later, `pip install -e .`, then `pip install pytest hypothesis` to
run the tests.

The values (not the counts in brackets) are checked against a recomputation that does not use
pandas, see [Tests](#tests). Two of them need care:

- **Washington's start hour.** From April, Washington's times are written on a 12-hour clock
  that lost its AM/PM mark, so an 08:00 can be a morning or an evening trip. The program reports
  the hours as recorded. [docs/results.md](docs/results.md) also gives the most common hour of
  January to March alone, when the clock was still 24-hour.
- **Long trips.** New York City and Washington have trips of several days. They are recorded
  durations and stay in the totals; [docs/results.md](docs/results.md) shows the mean without
  them.

## The data

The data are not stored in this repository. `scripts/fetch_data.py` downloads
`Bike_raw_data.zip` from the fulll repository at a pinned commit, checks the archive and each
file against its SHA-256, and extracts `chicago.csv`, `new_york_city.csv` and
`washington.csv` into `data/`. The bike share operators' licences do not allow publishing the
data as a stand-alone dataset, and the fulll repository has no licence: see
[docs/references.md](docs/references.md).

Each file holds the six columns of the statement (Start Time, End Time, Trip Duration, Start
Station, End Station, User Type), an unnamed row id that the program does not load, and, for
Chicago and New York City only, Gender and Birth Year. Before any statistic was computed, the
files were inventoried; [docs/data_quality.md](docs/data_quality.md) gives every figure. In
short:

- every timestamp is in the layout `2017-06-23 15:09:32`, although the statement prints them
  day first (`23/06/2017 15:09:32`);
- Washington's timestamps are at whole minutes until March and on a 12-hour clock from April,
  so its End Time is unreliable for thousands of trips: travel times come from the Trip
  Duration column, never from End Time minus Start Time;
- Washington stores durations with decimals, the other two in whole seconds;
- a few rows are identical to another in every column but the row id; they are kept, and
  removing them changes no most common value;
- user types, genders and years of birth are missing for some trips, and some years of birth
  are implausible (a rider born in 1885);
- some Washington station names carry stray spaces.

## How the statistics are computed

- **Return values.** Each statistics function prints a report and returns a dictionary whose
  keys follow the provided test (`mostCommonMonth`, `mostCommonTrip`, `totalTravelTime`,
  `userTypeCounts`, ...). Months and days are lower-case English names, as in that test.
- **Ties.** A most common value is a list holding every tied value, in natural order: calendar
  order, Monday to Sunday, hours and years ascending, stations alphabetically. Counts are listed
  from the largest, then by name. Results never depend on the order of the rows.
- **Most common trip.** Counted on ordered (start, end) pairs with one group-by: A to B and B
  to A are different trips, and the result is not the busiest start station paired with the
  busiest end station.
- **Timestamps.** Two layouts are accepted, the files' own and the statement's day-first one,
  and nothing is guessed: `03/04/2017` is 3 April, `06/23/2017` is refused rather than read
  month first. An unreadable start time is left out of the time statistics and counted in the
  report.
- **Durations.** In seconds, from the Trip Duration column. A missing, non-numeric, infinite or
  negative duration is left out and counted; zero is kept. With no usable duration, total and
  mean are `None`, never 0, so nothing is ever divided by zero.
- **Missing data.** A column that does not exist (gender and year of birth in Washington) gives
  `None` and "not available in this data set"; a column that exists but is empty gives `{}` or
  `[]` and "no value recorded". Trips with no value are counted in the report, never as zero.
- **Years of birth.** Whole numbers only, reported as recorded. The trips of riders not yet born
  or over 100 at the trip date are counted in the report, since the statement gives no cut-off.
- **Filters.** On the start time: a month from January to June, a day from Monday to Sunday,
  `all` for no filter, and both together. `load_data` cleans its arguments like typed answers
  and refuses unknown values; an empty selection prints "No trip matches these filters."

## Tests

```sh
uv run pytest                            # everything, the official data included
uv run pytest -m "not realdata"          # without the official data, in a few seconds
uv run python -m unittest                # the provided file alone, as a unittest suite
uv run python scripts/mutation_check.py  # do the tests notice calculation mistakes?
```

| File | What it checks |
|---|---|
| `test_bike_investigation.py` | The provided file, completed: the four statistics on small frames whose results can be checked by hand, including ties, missing columns, missing values, invalid durations and years, empty frames, unused categories and day-first dates. |
| `tests/test_cli.py` | `get_filters` and `main` with scripted answers: case and spaces, invalid answers asked again, restart, closed input and Ctrl-C at every question. |
| `tests/test_load_data.py` | Reading, typing and cleaning, then every month, every day and their 42 combinations on a small synthetic file whose trips per month and day are known; refused arguments, missing files and columns. |
| `tests/test_synthetic_results.py` | End-to-end results on three synthetic files built so that shortcuts give a wrong answer: the busiest trip is not the pair of busiest stations, and ignoring the direction of a trip changes the winner. |
| `tests/test_properties.py` | Hypothesis: random small frames (ties, missing values, numbers stored as text, rows in any order) compared with a plain Python recomputation; `get_filters` never fails on arbitrary text. |
| `tests/test_real_data.py` | The official files: their SHA-256, 300,000 trips each, and every statistic for 17 selections per city equal to a recomputation that reads the files with the `csv` module and counts with `collections.Counter`. |

`scripts/mutation_check.py` plants 26 plausible mistakes in a copy of the program, one at a
time (a month filter shifted by one, a tie cut down to one value, a negative duration kept,
the busiest trip built from the two busiest stations, a day and a month swapped...), and fails
if the tests still pass with any of them. All 26 are caught; the provided file alone catches
18, which is why the suite has several layers.

GitHub Actions runs on every push, with Python 3.11 and 3.14: lint and format checks, the data
download, and the whole test suite with the official data required, so that a missing file
fails the run instead of skipping the integration tests. With Python 3.14 it also checks that
the generated documents are up to date and runs the mutation check.

## Project layout

```text
bike_investigation.py       the program: the provided skeleton, completed
test_bike_investigation.py  the provided unittest file, completed
tests/                      pytest suite, and small synthetic CSV files in tests/data/
scripts/fetch_data.py       downloads and checks the official data into data/
scripts/make_docs.py        writes docs/data_quality.md, docs/results.md and two blocks of this README
scripts/benchmark.py        measures time and memory and writes docs/performance.md
scripts/mutation_check.py   plants mistakes to check that the tests notice them
docs/                       data quality, results, performance, references
```

The program stays one module, as provided: `main` asks `get_filters`, passes the answers to
`load_data`, then calls the four statistics functions. Small private helpers do the rest:
cleaning answers and station names, finding the data folder, parsing timestamps with the two
accepted layouts, reading a file into typed columns, computing modes with their ties, and
formatting counts.

## Technical choices

- **pandas 3.1 on Python 3.11 or later.** The skeleton pinned pandas 1.3.5 and numpy 1.23.4,
  which install together from wheels only up to Python 3.10, now past its end of life. numpy
  is no longer a direct dependency: the program does not import it, and `uv.lock` records the
  version pandas brings.
- **uv and a committed `uv.lock`**, so that the same versions are installed everywhere; CI
  uses `uv sync --locked`, which fails if the lock is stale.
- **pandas without row loops.** Only the known columns are read; timestamps are parsed with
  explicit layouts; station names, user types and genders are categories; most common values
  come from `value_counts`, the busiest trip from one `groupby` on the two station columns, and
  filters are boolean masks on the start time.
- **Hypothesis, for two properties only.** In the mutation check they were the only tests to
  notice results that depended on the order of the rows, until an explicit test was added. Its
  pandas strategies are not used, since they are documented for pandas up to 2.2.
- **No Pandera.** For eight columns it would add several dependencies (pydantic and typeguard
  among them); `load_data` checks the required columns and converts each type explicitly, and
  the tests cover it.
- **Ruff** for linting and formatting.

[docs/references.md](docs/references.md) lists the documentation behind each choice.

## Error handling

| Situation | Behaviour |
|---|---|
| Unknown answer in the terminal | A message lists the valid answers and the question is asked again. |
| Ctrl-D or Ctrl-C at any question | "Input closed, goodbye.", no traceback. |
| Unknown city, month or day given to `load_data` | `ValueError` naming the expected values. |
| Missing CSV file | `FileNotFoundError` with the command that fetches it; `main` prints it and offers to restart. |
| File without a required column | `ValueError` naming the missing columns. |
| Unreadable timestamp, duration or year of birth | Left out of the statistic and counted in a note of the report. |
| No trip matches the filters | "No trip matches these filters.", no statistic is invented. |
| Column absent from a city file | "not available in this data set", and `None` in the result. |

## Performance

On the machine measured, loading a city and computing the four statistics takes about a quarter
of a second, and a loaded city takes seven to eight times less memory than with a plain
`pd.read_csv`. Each choice is compared with the plain alternative, and the statistics are timed
up to 3 million rows, by `scripts/benchmark.py`; [docs/performance.md](docs/performance.md)
records the figures and the machine they come from.

## Limitations

- Washington's hour of day is ambiguous from April (12-hour clock without AM/PM): its most
  common start hour mixes morning and evening trips. Nothing in the data can restore the lost
  AM/PM, so the program does not try.
- End Time is not used for any statistic, and is wrong for thousands of Washington trips.
- Rows that look like trips recorded twice are kept, since nothing proves they are errors.
- Implausible years of birth are reported as recorded and flagged, not filtered.
- A whole city is loaded in memory, which is small here; a much larger file would need reading
  in chunks.
- The interface is in English, and months stop at June, as in the data set and the skeleton.
- The performance figures come from one machine.
- The licence reading in [docs/references.md](docs/references.md) is not legal advice.

## Changes to the provided files

Problems found in the skeleton, each reproduced on a copy of the original files:

1. `pyproject.toml` does not parse: a comma is missing between the two dependencies
   (`TOMLDecodeError: Unclosed array`).
2. With the comma added, the project still does not build: setuptools stops on the two
   top-level modules ("Multiple top-level modules discovered in a flat-layout") and warns that
   `README.md` is missing. `py-modules` now names the program.
3. pandas 1.3.5 has wheels up to Python 3.10 only, and numpy 1.23.4 fails to build on
   Python 3.12 or later (`No module named 'distutils'`).
4. `License :: OSI Approved :: Private` is not a registered classifier; `Private :: Do Not
   Upload` is the one PyPI documents to block an accidental upload.
5. `test_bike_investigation.py` does not compile (a function without a body) and uses `df`
   before defining it.
6. In `bike_investigation.py`, `get_filters` and `load_data` return names that are never
   defined, numpy is imported but unused, and the statistics functions return nothing although
   the test reads a dictionary.
7. `main` ended the program on any answer other than exactly `yes` (` yes` and `y` included)
   and crashed on a closed input.
8. The statement shows dates day first and durations as whole seconds, while the files hold
   ISO-like dates and, for Washington, decimal durations.
